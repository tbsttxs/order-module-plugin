# 老品下单执行器使用说明

> 适用范围：采购系统 **老品下单**。新品下单不适用本流程。
>
> 输入：Excel 仅填写 `料号*`、`下单数量*`。

## 一、它会做什么

完整执行模式会按已验证规则逐行处理：

```text
料号精确查询
→ 状态选择“未处理”
→ 仅勾选搜索结果第一条
→ 分仓模拟
→ 确定分配
→ 将计划采购数改为 Excel 数量
→ 重新发起分配
→ 校验分配总数
→ 保存分仓方案（PN）
→ 生成采购计划（PP）
→ 提交
→ 审核通过
→ 回写结果 Excel 与运行台账
```

## 二、首次使用准备

每位采购人员各自在自己电脑上使用，并使用**自己的采购系统账号**登录。程序不保存账号、密码、Cookie 或 SSO Ticket。

需要：

```text
Windows 10/11
Node.js LTS（建议 20 或更高）
Google Chrome
采购系统正常登录权限
```

执行器文件夹：

```text
桌面\老品下单执行器```

首次使用时，在该文件夹双击：

```text
启动专用采购Chrome.cmd
```

会打开一个“专用采购 Chrome”。请在这个窗口中按公司正常流程登录采购系统。不要关闭该窗口，直到任务结束。

> 如果提示 Chrome 路径找不到，请联系维护人员修改 `启动专用采购Chrome.cmd` 中的浏览器路径。

## 三、准备输入表

使用统一模板，用户只需要填写两列：

| 料号* | 下单数量* |
|---|---:|
| SPC000269_CLB | 100 |

规则：

- 一行代表一个任务；
- 料号不能为空；
- 下单数量必须是大于 0 的数字；
- 建议一次只放已完成内部审批的任务；
- 不要在执行时打开或编辑同一个 Excel 文件；
- 每次运行前将 `config.json` 中的 `inputWorkbook` 改成当前待执行 Excel 的完整路径。

示例：

```json
{
  "inputWorkbook": "C:/Users/你的用户名/Desktop/本次老品下单.xlsx"
}
```

## 四、先做只读验证（推荐）

双击：

```text
运行只读验证.cmd
```

只读验证会：

```text
精确查询料号
→ 选择状态“未处理”
→ 检查第一条需求
→ 回写采购需求编号和验证结果
```

它**不会**分仓、创建 PN/PP、提交或审核。

适用场景：

- 第一次使用；
- 新账号验证权限；
- 页面改版后验证；
- 批量正式执行前抽查数据；
- 确认第一条“未处理”需求是否就是要处理的记录。

## 五、正式完整下单

确认输入表无误、专用 Chrome 已登录、且本批任务已获得业务授权后：

1. 双击：
   ```text
   运行完整下单.cmd
   ```
2. 程序会提示：
   ```text
   输入 YES 后开始：
   ```
3. 只有输入大写 `YES` 才会实际开始。

执行期间：

- 不要关闭专用 Chrome；
- 不要手动点击采购系统页面；
- 不要关闭命令窗口；
- 不要编辑输入 Excel；
- 一条发生异常时，程序记录异常后继续处理下一条。

## 六、如何看结果

每次运行都会在以下目录生成独立结果：

```text
桌面\老品下单执行器
uns\<运行时间>```

包含：

| 文件 | 用途 |
|---|---|
| `结果-原文件名.xlsx` | 自动回写后的结果表，可提供给业务人员查看/归档 |
| `run.json` | 完整机器可读台账，记录每行 SKU、DM、PN、PP、时间、状态与异常 |
| `screenshots\` | 异常/证据截图目录（若页面允许截图） |

结果 Excel 中重点看：

| 字段 | 含义 |
|---|---|
| 采购需求编号 | 本次实际选择的 DM |
| 采购计划号 | 已生成的 PP |
| 执行结果 | `成功`、`只读校验通过` 或 `异常` |
| 异常说明 | 停止原因与排查信息 |
| 开始时间 / 结束时间 | 本行任务执行时间 |

`成功` 的含义是：已完成分仓、生成 PP、提交，并且系统状态已回读为 **审核通过**。

## 七、固定业务选择规则

程序不会自动汇总同一料号的多条需求，也不会选择多条记录：

```text
料号精确查询
+ 状态=未处理
+ 始终只选择搜索结果第一条
```

如果第一条不是正确业务需求，请不要执行完整下单；应先由采购人员在系统中核对或调整业务数据。

## 八、常见异常与处理

| 现象 | 处理方式 |
|---|---|
| 提示登录态失效 | 在专用采购 Chrome 中重新登录后重跑未完成行 |
| 未找到未处理需求 | 核对料号、状态和是否已被处理；不要强行重复下单 |
| 分配总量不等于输入数量 | 程序会停止该行；检查供应商、区域、库存/分配规则和料号主数据 |
| 体积、供应商、价格等主数据异常 | 程序会停止该行；先在采购系统维护主数据 |
| 页面加载很慢/截图失败 | 不影响已验证的业务状态回读；查看 `run.json` 和结果 Excel |
| 某行失败 | 检查该行的异常说明；修正后仅保留失败行重新执行 |

## 九、重要注意事项

1. 正式模式会创建真实采购计划并审核通过，必须只处理已获授权的数据。
2. 不要重复运行同一份已成功的输入行。目前每次执行按“当时第一条未处理需求”处理；跨批次防重复校验仍在增强中。
3. 不要把账号、密码、Cookie、SSO Ticket 写进 Excel、配置文件或聊天。
4. 新品下单必须另做流程，不能直接使用本工具。
5. 浏览器页面结构改版后，应先运行只读验证再进行正式下单。
