# 新品下单模块（本地原型）

当前范围：采购系统「预警管理 → 美西仓库料号预警」的新品下单流程。

> 此目录当前仍处于受控试用阶段。批量正式下单、结果回写与异常分派机制需在业务人员试用确认后再固化。

## 已确认流程

1. 登录采购系统；
2. 进入 `美西仓库料号预警`；
3. 类型固定为 `料号子SKU`；
4. 用 Excel 的料号逐行精确查询；
5. 仅处理唯一查询结果；
6. 勾选结果，点击 `生成采购订单`；
7. 在「非预警下单」弹窗中备注 `新品`；
8. 提交，成功页点击 `OK`；
9. 采购管理 → 待审核，搜索类型选择 `SPU&SKU`，精确搜索同一料号；
10. 勾选目标订单，经 `操作 → 编辑` 进入编辑页；
11. 将订购数量改为 Excel 的目标数量，备注 `新品`，点击 `保存单据`；
12. 捕获本次保存后新出现的右下角 `保存成功`，点击 `返回`；
13. 再次经 `待审核 → SPU&SKU → 勾选 → 操作 → 编辑` 回读订单号、数量和备注后，才回写成功。

页面中的主体、需求模块、部门等归属信息遵从采购系统当前记录与权限；工作台不擅自修改不可编辑字段。新品初始下单数量由系统流程默认生成 `1`；最终数量以编辑页回读结果为准。

## 保存单据的受控重试

采购系统保存存在已确认的系统级不稳定：首次点击可能约一分钟后成功，也可能快速发生无内容保存的页面变化；后者再次点击后才可能真正提交。

| 阶段 | 判断与动作 |
|---|---|
| 首次保存 | 每次点击前重填并核验订单号、SKU、目标数量、备注；点击后持续监听本次新出现的右下角 Toast `保存成功`，最长等待 `75 秒`。 |
| 45 秒检查点 | `45 秒`仍无 Toast 时，继续观察至 `75 秒`；若发生无 Toast 的跳转/重载，则立即视为首次未确认。 |
| 第二次保存 | 首次未确认后，重新定位编辑页、重新填写数量和备注，再点击一次；同样最长等待 `75 秒`。 |
| 成功 | 必须同时满足：本次新增可见 Toast `保存成功`、已返回、重新经 `操作 → 编辑` 回读数量和备注都匹配。 |
| 失败/待确认 | 两次都没有有效 Toast，或 Toast 后回读不一致：停止，不再自动重试；回写 `部分完成/待确认`、订单号、两次尝试时间、页面状态和回读值。 |

禁止用 `body.innerText.includes('保存成功')`、输入框暂时保留，或列表短暂刷新作为成功判断；这些均可能是静态文本或假跳转。

## 异常回写规范（必须执行）

系统没有充分的前置校验。任何在「生成采购订单」或「提交」阶段才暴露的业务阻塞，都必须被沉淀为可分派的维护事项，而不是仅写“下单失败”。

结果 Excel 每行至少包含：

| 字段 | 含义 |
|---|---|
| 料号 | 当前处理的精确料号 |
| 下单数量 | 本次请求数量或系统默认数量 |
| 执行结果 | 成功 / 未创建订单 / 预览完成 |
| 阻塞环节 | 最后一个已验证的业务步骤 |
| 系统原始提示 | 系统返回的原始报错文本 |
| 待维护项目 | 需要维护的主数据或配置名称 |
| 待维护动作 | 维护人员需要做的明确动作 |
| 当前值 / 证据 | 已知现状、页面记录或截图路径 |
| 建议协同对象 | 以业务责任矩阵配置的角色或维护组；不由程序猜人 |
| 处理状态 | 待维护 / 已反馈 / 已修复 / 待复测 |
| 开始时间 / 结束时间 | 北京时间 |

### 已验证案例

| 字段 | 值 |
|---|---|
| 料号 | `YPA000900_2` |
| 下单数量 | `1` |
| 执行结果 | 未创建订单 |
| 阻塞环节 | 生成采购订单（提交「非预警下单」弹窗后） |
| 系统原始提示 | `YPA000900_2未设置运输方式,请先设置` |
| 待维护项目 | 料号运输方式 |
| 待维护动作 | 在采购系统中为 `YPA000900_2` 维护有效运输方式后，重新执行新品下单。 |
| 当前值 / 证据 | 系统返回该提示；本次未生成采购订单。 |
| 处理状态 | 待维护 |

## 设计原则

- 每行独立处理：一行异常必须回写后继续下一行；
- 失败信息要能直接转给维护方：说明“哪个料号、缺哪个配置、在哪里维护、维护后如何验证”；
- 不猜测维护责任人：责任人/维护组应由后续维护矩阵配置；
- 创建或提交后必须回读结果；点击按钮不等于成功；
- 所有时间使用任务完成时的北京时间，文件名为 `新品下单-YYYY-MM-DD-HHmm.xlsx`。

## 本地运行

```bash
npm install
npm start
```

工作台监听 `127.0.0.1:8790`。使用前在专用采购 Chrome 登录，CDP 仅绑定 `127.0.0.1:9333`。

> 当前原型的 Playwright / keytar 依赖来自已安装的老品工作台，正式产品化前应通过本仓库 `npm install` 固化依赖。不要提交采购账号、密码、Cookie、SSO ticket、Chrome Profile、运行结果或日志。
